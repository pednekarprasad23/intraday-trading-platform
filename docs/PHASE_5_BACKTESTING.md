# Phase 5 — offline option-premium simulation (bounded vertical slice)

This is a research simulation, **not** exchange/broker fills, paper orders, or a forecast of live performance. No network/provider/order interfaces are used. The operator CLI reads explicit completed 1m/5m sessions from the Phase 3 Parquet catalog; it checks contract identity (underlying, strike, expiry, CE/PE), provider mapping, catalog counts and gap records, exact expected path, bounded file size, SHA-256, Parquet schema, UTC row ordering and complete session coverage. Missing sessions are errors, never inferred holidays. Relative-strike/rolling metadata is rejected by the reader. Contract selection is explicit by instrument ID; automated strike/expiry selection is **not implemented**.

Example after importing several complete exact-contract sessions with the configured historical data root:

```text
python -m app.cli backtest --provider DEMO --instrument-id <uuid> --timeframe 1m --dates 2026-11-02 2026-11-03 2026-11-04 --quantity 1 --fee-per-side 1 --tax-rate 0.01 --slippage 0.1 --spread 0.2
python -m app.cli walk-forward --provider DEMO --instrument-id <uuid> --timeframe 1m --dates 2026-11-02 2026-11-03 2026-11-04 --train-size 2 --test-size 1
```

The built-in Phase 4 EMA/RSI strategy evaluates each completed bar on a contiguous within-session window (at most 500 bars). Earliest simulated entry is the next bar's open. A signal without a subsequent entry **and** exit bar produces NO_FILL. Only one long position per option contract; all positions end within the same session, with expiry sessions also closed. The last completed bar's close is an assumed session exit, not an actionable auction fill. Stop/target intrabar ambiguity always chooses stop; a gap below stop uses the worse open; target gaps cap the exit at target. The entry bar's high/low are ignored because their sequence relative to the open is unknown. Prices include configurable adverse spread and slippage, two-sided flat fees and turnover taxes. Quantity is a positive Decimal input, not inferred lot sizing. No volume-based liquidity or capacity model exists; OHLCV fills and costs are assumptions. The event/trade ledger and SHA-256 fingerprints are returned in memory/CLI only.

Walk-forward uses expanding training sessions and non-overlapping chronological test blocks. Candidate configs are supplied as a bounded built-in-strategy tuple through Python; selection maximizes **training-only** net P&L, ties use candidate order, and the selected config is frozen on test. The CLI currently supplies one candidate, so it demonstrates chronological out-of-sample execution, not hyperparameter optimization. Every input session must meet configured minimum bar coverage; a trailing incomplete fold is omitted. No cross-contract portfolio, capital/margin model, intrabar sequence reconstruction, automatic holiday calendar, persisted run/ledger migration, authenticated report API, broker-backed data verification, or Phase 6 execution is implemented. Synthetic 4-session test fixtures exercise deterministic replay and leakage boundaries; they are not evidence of statistical performance.
