# Read-only research reporting (pre-Phase-6)

The signed-in Research section reads persisted accepted LONG signal snapshots, newly persisted operator evaluations (LONG/NONE/rejected), and simulated backtest/walk-forward reports. It does not scan live ideas or recommend trades. Older `NONE` and rejected evaluations cannot be reconstructed retroactively. A blank dashboard means no qualifying operator-created record, not that a setup was tested and failed. No paper orders, broker fills or execution interfaces exist.

## Dhan operator flow

Dhan tokens are entered only via the interactive operator command `python -m app.cli credential-save-dhan` (hidden prompt). First initialize the encryption key with `python -m app.cli credential-init` inside the API container after migrations. This generates a restricted key in the dedicated `credential_key` Docker volume, **outside PostgreSQL**; back up this key securely and separately from the database, because without it stored ciphertext cannot be recovered. Existing key initialization refuses to overwrite it. Rotating the Dhan token uses the same save command; `credential-delete-dhan` removes it. No token appears in CLI arguments, shell history, browser requests, API routes or logs. CLI Dhan history commands decrypt the token on demand; an explicit ephemeral `DHAN_ACCESS_TOKEN` operator-process override remains possible. Do not commit the token or key. Both key volume and PostgreSQL backup are sensitive; treat both as confidential and restrict host/Docker access. This is a single local operator boundary, not a multi-tenant secret manager: anyone with API-container exec or both the database and key can access the token. The read-only adapter uses fixed HTTPS chart endpoints and a bounded response/time window. Verify subscription rights, Dhan master/security-ID mapping, original timestamps/price units, exchange session and contract continuity independently before claiming a real exact-contract sample. Confirm the authorized research/storage use before retaining normalized output.

For a rolling, **non-contract** coverage check, the operator supplies `dhan-rolling-check --security-id <underlying-id> --exchange-segment NSE_FNO --instrument-kind OPTIDX --timeframe 1m --session-date <YYYY-MM-DD> --session-start 09:15 --session-end 15:30 --expiry-flag MONTH --expiry-code <verified-code> --relative-strike ATM --option-type CE`. The command reports CE/PE count, missing slots and sanitized response hash; it does not import a partition or backtest. The rolling endpoint selects one option type and its other response branch may be null.

For an **active exact-contract** sample, first import an independently verified, non-demo `DHAN` instrument/master mapping, with known underlying, expiry, strike, CE/PE and matching security ID. Run `dhan-exact-import` with `--security-id`, matching `--provider-key`, `--instrument-id`, `--exchange-segment NSE_FNO`, `--instrument-kind OPTIDX`, `--expiry`, `--strike`, `--option-type`, `--timeframe`, `--session-date`, `--session-start`, `--session-end`. The command refuses mismatched metadata, gaps and duplicate bars, then normalizes to the existing immutable CSV/Parquet catalog. It prints both the sanitized provider-response SHA-256 and normalized fixture SHA-256; the catalog stores the normalized fixture hash and separately records the sanitized provider-response hash and UTC retrieval time. It does not retain raw provider responses. Network failure, incorrect timestamp/price semantics or absent entitlement must be recorded as blocked, never replaced with DEMO performance.

After a completed exact-contract import, use `evaluate-catalog --instrument-id <uuid> --provider DHAN --timeframe 1m --session-date <date>` to persist an evaluation directly from verified Parquet without needing the temporary normalized CSV. `evaluate-strategy` remains the retained-fixture workflow. `backtest` and `walk-forward` also run offline. `backtest` and `walk-forward` persist idempotent result projections with source partition hashes, configuration and warnings. Reports are not a complete trade/event archive: detail arrays are capped at 100; use source fingerprints and CLI replay for audit. Read-only, authenticated endpoints are `/api/v1/research/signals`, `/api/v1/research/evaluations`, `/api/v1/research/backtests`, `/api/v1/research/walk-forwards` (limit 1–100, nonnegative offset), with report detail at `/backtests/{id}` and `/walk-forwards/{id}`. Dashboard results are always labeled RESEARCH ONLY / SIMULATED / NO BROKER ORDER. No calculated metric establishes profitability or predicts live results.

Its single-day evaluation and simulation are visible in the authenticated research catalog; no accepted final-checkpoint LONG was recorded (`VALID NONE`).
